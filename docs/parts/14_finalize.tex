\section{The geometry pass: indices and lazy vertices}
\label{sec:finalize}

\subsection{One dispatch, two outputs}

The host sizes both spans before submission:
\begin{equation}
  V_{\text{cap}} = \text{activeVertexCount},\qquad
  I_{\text{cap}} = \text{cross-edge topology bound}
\end{equation}
(see Section~\ref{sec:gpudesign}).  The geometry dispatch then runs one
invocation per compacted scan cell:
\begin{lstlisting}[style=glsl,caption={Geometry stage.},label={lst:geometry}]
void main() {
    uint gi = gl_GlobalInvocationID.x;
    if (gi >= pc.cellCount) return;
    scanCell(cellIds[gi]);
    if (pc.diag != 0u) { /* publish findCell/reuse counters */ }
}
\end{lstlisting}
Each invocation appends its triangles straight into the chunk's index span
and lazily writes the vertex payload of every referenced slot.  There is no
intermediate raw-key stream, no second work list, and no host round trip
between indices and vertices.

\subsection{Index values}

Every index is the host-assigned slot of the emitting surface node:
\begin{equation}
  \text{slot} = \text{nodeSlot}(\text{node}) = (\text{flags}\gg1)-1.
\end{equation}
If the slot is negative, the host's slot assignment and the walk disagree.
The shader increments \code{invalidSlotCount} and \code{droppedCount} and
fails the chunk rather than writing slot 0.  Writing 0 would silently
connect the corner to an arbitrary vertex and produce a stretched triangle.
This condition is not retryable: more capacity cannot fix a flattening
disagreement.

\subsection{Vertex reconstruction}

The vertex is rebuilt from the node, not carried through an intermediate
stream:
\begin{enumerate}
\item QEF position from the node's eight corners and cube;
\item analytic normal at that position;
\item brush, falling back to the chunk's \code{fromBrush} when the node's
   brush is the discard sentinel;
\item HSV tint, texture type, and mapping data.
\end{enumerate}
The payload is a pure function of the node.  The first invocation that
references a slot wins the \code{atomicExchange} on \code{nodeWritten} and
writes the payload; the others do nothing.  This keeps the traffic at one
64-byte write per referenced node even though a node appears in many
triangle corners.

\subsection{The index base and alignment}

The chunk's index span is bound with an offset.  The offset must be aligned
to the device's minimum storage-buffer offset alignment.  Since the element
size is four bytes and the alignment can be 256, the host aligns the
descriptor offset down and passes \code{relIndexBase} = the number of index
elements between the aligned offset and the first span element.  The shader
writes
\begin{equation}
  \text{poolIdx}[\text{relIndexBase} + i] = \text{slot}.
\end{equation}
The descriptor range is
\begin{equation}
  (\text{relIndexBase} + I_{\text{cap}})\cdot4
\end{equation}
bytes, which includes the padding.  Without the extra padding, the last
elements of the span fall outside the bound range and are never written,
producing stretched triangles from stale pool data.

\subsection{The vertex base and alignment}

The vertex span is handled the same way with a 64-byte stride.  The offset
is aligned down; \code{relVertexBase} accounts for the 0--3 element
padding.  The shader writes
\begin{equation}
  \text{poolVerts}[(\text{relVertexBase} + s)\cdot4 + k].
\end{equation}
The range is
\begin{equation}
  (\text{relVertexBase} + V_{\text{cap}})\cdot64.
\end{equation}
Because 64 is a multiple of 4 and the largest required alignment is 256, a
span start can be misaligned by at most three vertices.  The padding logic
is exact and costs at most 192 bytes per chunk.

\subsection{Overflow accounting and growth}

The shader never writes outside the reserved spans.  A triangle that does
not fit still advances the index counter and updates the maximum referenced
slot, so the host reads:
\begin{center}
\begin{tabular}{@{}ll@{}}
\toprule
Counter & Meaning\\
\midrule
\code{indexCount} & indices the chunk would need (3 per triangle)\\
\code{vertexExtent} & highest referenced slot + 1\\
\code{indexOverflow} & triangles rejected by the index span\\
\code{vertexOverflow} & triangles rejected by the vertex span\\
\code{invalidSlotCount} & corners without a host-assigned slot\\
\bottomrule
\end{tabular}
\end{center}
If an overflow is reported, the service frees this chunk's reservation and
asks the provider for
\begin{equation}
  I_{\text{next}} = \max(I_{\text{cap}}, \text{indexCount}),\qquad
  V_{\text{next}} = \max(V_{\text{cap}}, \text{vertexExtent}),
\end{equation}
then retries the dispatch with the same input and a freshly cleared
\code{nodeWritten} buffer.  The retry is bounded (three attempts) and
scoped to one chunk; there is no global rebuild or device wait.  A fixed
break-list overflow or an invalid slot is not retryable and fails the chunk.

\subsection{Empty chunks}

A chunk with no crossing scan cell, or with no surface node in the flattened
table, has no possible triangle.  The service reports success with zero
geometry and does not ask the pool for a zero-sized span.  The publisher
settles the revision as empty, so a later edit that introduces a surface
rebuilds it normally.
